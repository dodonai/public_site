Complete SOP example 1

New matter setup and folder structure

Representative current-state SOP. Names, systems, folder labels, and selected facts have been generalized or altered.

Status: current-state baseline. The firm corrects and approves this record before implementation begins.

Scope

Covers the work from a new client or deal request through assignment of a matter ID and creation of the shared workspace. Drafting the first substantive documents and filing matter email live in companion SOPs.

Inputs and systems

New request, cloud document repository, practice-management system, email handoffs, and the firm's informal folder and naming conventions.

Originating attorney

Owns the legal choice
  • Chooses the correct client, matter, and legal structure.
  • Opens the working space.

Operations manager

Owns the canonical record
  • Creates the matter in the practice-management system.
  • Assigns the matter ID.

Associate

Works the matter
  • Confirms unclear matter IDs.
  • Works inside the shared matter structure.

Legal support

Maintains the file
  • Files documents and prepares execution materials.
  • Maintains assigned work product inside the workspace.

Failure points and controls

Where the process breaks, and how the firm catches it

01Current-state control gapSOP finding
Where it breaks
  • Attorneys create different folder trees.
  • The matter ID is missing from file and folder names.
  • Similar names create billing and filing uncertainty.
  • Working and final files can sit together.
  • Routine questions interrupt operations.
→
Controls today
  • The originating attorney corrects deviations when noticed.
  • The drafts/final convention works when followed.
  • Staff ask operations or the drafting attorney.
  • The repository lacks a check for the folder set and matter ID.

C

Seed the workspace with the correct forms for the selected matter type.

D

Exception queue

Route ambiguous client, matter, or entity choices to the right owner.

Complete SOP example 2

Signature packets and execution tracking

Representative current-state SOP. Names, systems, document counts, and selected facts have been generalized or altered.

Status: current-state baseline. This captures packet creation, routing, returns, completeness, and reassembly.

Scope

Covers building signer-specific packets from the final document set, routing execution, tracking returns, checking completeness, and reassembling executed documents.

Inputs and systems

Attorney instructions, final documents, matter workspace, PDF assembly software, electronic signature, email, and courier service.

Legal support

Owns execution operations
  • Builds and routes packets.
  • Tracks, checks, and reassembles returns.

Deal attorney

Owns legal scope
  • Selects documents and signers.
  • Sets the deadline and approves exceptions.

Signatories

Complete execution
  • Sign electronically or in wet ink.
  • Return the required pages and originals.

Outside parties

Supply external instructions
  • Provide their document packets.
  • Set applicable execution requirements.

Failure points and controls

Small misses become closing-day problems

02Current-state execution riskSOP finding
Where it breaks
  • A missed page or signer stays hidden until late.
  • Last-minute changes create re-execution work.
  • Packet formats and instructions differ by attorney.
  • Version confirmation delays assembly.
  • Free-form email leaves the signer matrix undocumented.
→
Controls today
  • Legal support counts pages before routing.
  • Every return is checked by eye.
  • The deal team reviews the executed set.
  • Recipients can expose a missing item after delivery.
Candidate automation

A controlled packet flow, with visible exceptions

A

Packet builder

Read the final set and approved signer matrix, then produce one packet per signer.

B

Routing rules

Apply electronic-signature and wet-ink requirements and surface exceptions.

C

Execution tracker

Show sent, viewed, signed, missing, and superseded status by document and signer.

D

Completeness and filing

Match returned pages to document bodies and save executed versions to the approved location.
