Gordon's Red Hen Operating System project defines four layers: systems of record that stay, a knowledge repository, structured data, and AI as the interface. Lisa's automation roadmap arrives at the same destination from the AP side: "how does trusted information move through Red Hen," so that software can come and go without the business reinventing itself. That shared idea has a name: an operating system for the farm. One structured, queryable store beneath the tools you keep, agents doing the routine work, and every approval staying human. This brief shows what it looks like built.

The other stuck point

The weekly spray loop, from the screen recording

Gordon recorded his actual weekly cycle on July 11. It is the functional spec for the chemical build, failure demos included.

🧪Chemicals & spray records · ~$750k/yrphase 3
Today
  • Handwritten rig records re-typed into Excel, then copy, paste, paste-values to break formulas. One formula has been broken for years.
  • The rig logs "Tomato 9," never the actual products. GPS coverage and chemical identity never meet.
  • Chemistry rules hand-noted on every work order; mid-flight rate changes scribbled in the margin.
  • Cost per field or per variety: "tying dollars to this has been a challenge."
  • SDS lives in a paper binder; label PPE requirements go unread.
→
With the OS
  • The operator taps actual rates once, from the cab. Effective-rate math (shut-off nozzles, tank rounding) is computed, not lore.
  • JD Ops as-applied coverage joins to real product identity and cost, per field, per variety, per block.
  • Tank-mix bans, the 5-day herbicide window, 48-hour re-entry, and 30-day listings checked automatically on every plan.
  • Pick sheets, tank batches, and Red Gold reports are generated, not assembled.
  • Every SDS and label PPE requirement one tap away for any employee.

BILL.com

Great at: ACH payments, approval chains, Positive Pay

Where it breaks: it sits at the payment end. The bottleneck Lisa documented is upstream: coding rules no tool retains. BILL still needs correctly coded bills flowing into it.

ChatGPT + Zapier, DIY
advisor + glue

Great at: architecture thinking. It got RHOS this far.

Where it breaks: someone still has to build, integrate, and maintain it. Prior builds stalled exactly there, and left systems nobody dared touch.

Dodonai — build & own
implementation partner

Great at: building the store, the agents, and the integrations as one owned, maintainable system, with the learning rules layer no off-the-shelf tool offers

Best fit when: the goal is a durable information architecture where software can come and go. Payment rails stay an open, later decision that clean data makes easy either way.
